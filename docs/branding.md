# TimeClaim branding

The user-supplied `Group.svg`, preserved unchanged as
`assets/branding/timeclaim-source.svg`, is the geometry source. Its compound path
contains a rounded tile and five monogram cutouts. Generation removes only the tile
and fills the original monogram paths with the mint gradient from the first image.
The original proportions and path coordinates are preserved with uniform scaling;
there is no hand-redrawn replacement. Native icons use a full-bleed square navy
gradient without pre-rounded corners, shadows or checkerboard.

## Sources and generation

- `assets/branding/timeclaim-source.svg`: original user-supplied `Group.svg`; authoritative geometry.
- `assets/branding/timeclaim-symbol.svg`: generated mint monogram on transparency.
- `assets/branding/timeclaim-icon.svg`: generated full-bleed square navy-gradient icon.
- `assets/branding/timeclaim-monochrome.svg`: generated white adaptive-icon silhouette.
- `scripts/generate-branding.py`: extracts the original monogram paths, applies the colors,
  and generates all SVG/PNG/ICO variants. Edit colors here, not in generated assets.

Requires Python 3, ImageMagick (`magick`) and librsvg (`rsvg-convert`), with no Python
packages or extra npm dependencies:

```sh
npm run branding:generate
npm run branding:check
```

Commit the sources and generated assets together. The build does not require the
image-generation tools. `branding:check` verifies dimensions, opacity, monochrome
pixels, Android safe-zone compliance and configured PNG paths.

## Asset mapping

| Use | Asset | Notes |
| --- | --- | --- |
| iOS / generic / legacy Android | `assets/images/icon.png` | 1024×1024, opaque RGB, no baked-in corners; Expo generates native sizes |
| Android adaptive background | `assets/images/android-icon-background.png` | 1024×1024, opaque full-bleed navy gradient |
| Android adaptive foreground | `assets/images/android-icon-foreground.png` | 1024×1024, transparent, glyph fits the central 66/108-diameter safe circle |
| Android themed icon | `assets/images/android-icon-monochrome.png` | Same safe zone, white silhouette with transparent negative space; Android supplies the color |
| Native splash | `assets/images/splash-icon.png` | 512×512 transparent monogram on configured navy background |
| Reusable logo | `assets/branding/timeclaim-logo.png` | 1024×1024 transparent monogram, no tile |
| Google Play listing | `assets/branding/google-play-icon.png` | 512×512 opaque square; upload without adding corners or drop shadow |
| App Store | `assets/images/icon.png` | 1024×1024 source; native asset catalog generated by Expo |
| Browser favicon | `assets/images/favicon.png`, `public/favicon.ico` | 48px PNG plus 16/32/48px ICO |
| Apple web home-screen icon | `public/apple-touch-icon.png` | 180×180 opaque square |
| Web manifest | `public/icon-192.png`, `public/icon-512.png` | Standard web-app icons |
| Web maskable icon | `public/icon-maskable-512.png` | Separately padded for the central 80%-diameter safe circle |

`app.json` connects all native icons and the splash screen. The app header uses the
same icon; its UI-only rounded presentation is not baked into the source image.
`src/app/+html.tsx` links the Apple touch icon and `public/manifest.webmanifest` for
the web export. Web paths assume deployment at the domain root. The manifest does
not add a service worker or offline caching.

## Release verification

Icon/splash changes require a **new native build and installation**, not just an
OTA JavaScript update. Expo Go displays its own launcher icon. Launchers and browsers
can cache old icons; reinstall or remove/re-add the web home-screen entry if needed.

Before store release, inspect an installed build on iOS and Android, including
Android circle/squircle masks, themed icons and cold-start splash. Store screenshots,
Play feature graphics and other promotional artwork are separate deliverables, not
launcher icons generated by this pipeline.

Local validation: branding checks, TypeScript and ESLint pass. Web export currently
fails resolving the existing `expo-sqlite` `wa-sqlite.wasm` import; web icons are
prepared, but a working web release still needs that separate bundler configuration.
